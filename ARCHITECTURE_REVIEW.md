# Architecture Review
Generated: 2026-08-01T19:33:43.341Z
Score: 66/100

## Summary
The codebase has a clean, well-documented component library (Card/SummaryHero/BottomCTA/StateView) with consistent 'pre-built, don't reimplement' conventions, and no circular dependencies were found. However, there is significant duplication of small utility logic (haptic wrappers, date helpers, number formatting) across pages and components, an entire unused legacy contract file, and a couple of dead/scratch files left in the pages directory that should be removed or relocated.

## Issues
### Warnings
- [duplication] The exact same try/catch haptic-feedback wrapper (`fireHaptic`) is independently redefined in at least 5 places instead of being shared, each with a slightly different signature/typo surface. — Files: src/components/BottomCTA.tsx, src/components/CheckInSection.tsx, src/components/FloatingTabBar.tsx, src/pages/BudgetPage.tsx, src/pages/Home.tsx, src/pages/RecordPage.tsx / Fix: Extract a single `fireHaptic(type)` helper into e.g. src/lib/haptics.ts and import it everywhere; keeps the WebView-guard try/catch logic in one place.
- [duplication] `addDays(date, days)` is implemented identically (UTC date-math + zero-padding) in three separate files. — Files: src/lib/calc.ts, src/lib/store.ts, src/pages/StatsPage.tsx / Fix: Move addDays (and daysInMonth/dayOfMonth) into a shared src/lib/date.ts module and import from there.
- [duplication] `todayString()`/`todayDate()` (new Date().toISOString().slice(0,10)) is redefined in every page file instead of being a single shared utility. — Files: src/pages/BudgetPage.tsx, src/pages/Home.tsx, src/pages/RecordPage.tsx, src/pages/StatsPage.tsx, src/pages/SimulationPage.tsx / Fix: Add `today()` to the same shared date module and import it, removing all five local copies.
- [consistency] Two parallel, overlapping number/currency formatting utilities exist and are used inconsistently: `formatNumber` (lib/utils.ts, unit appended separately by callers) vs `formatKRW` (lib/format.ts, returns a combined '원' string). Amount/CountUp use the former, DonutChart/OverBudgetAlert use the latter, with no documented rule for which to use where. — Files: src/lib/utils.ts, src/lib/format.ts, src/components/Amount.tsx, src/components/CountUp.tsx, src/components/DonutChart.tsx, src/components/OverBudgetAlert.tsx / Fix: Pick one canonical formatter (e.g. formatKRW as the currency-specific one, formatNumber for generic non-currency counts) and document/enforce the split, or merge into a single module.
- [dead_code] src/lib/contract.ts defines a full parallel type/function-signature system (`Record`, `Budget`, `saveRecordFn`, `useRecordsFn`, `useAppStateFn`, etc.) that doesn't match the types actually implemented and used elsewhere (`MealRecord`, `MonthlyBudget`, `useAppData`, `useDerived` in lib/types.ts and lib/store.ts). None of these contract types/aliases appear imported anywhere in the codebase. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/store.ts / Fix: Delete contract.ts now that the real implementation (types.ts/store.ts) has superseded it, or update it to match reality if it's still meant to be a living spec.
- [dead_code] TossRewardAdMini.tsx is explicitly self-described in its own comment as unused debug scratch code left over from a prior session, not wired into any page/route. — Files: src/components/TossRewardAdMini.tsx / Fix: Delete the file (or if file deletion is genuinely blocked in this environment, move it out of src/components into a clearly-marked scratch/ directory excluded from the build).

### Suggestions
- [duplication] `digitsOnly()` and `formatThousands()` input-formatting helpers are duplicated verbatim between the budget and record forms. — Files: src/pages/BudgetPage.tsx, src/pages/RecordPage.tsx / Fix: Extract to src/lib/inputFormat.ts (or utils.ts) as shared numeric-input helpers.
- [consistency] lib/storage.ts exposes two overlapping localStorage read/parse mechanisms — generic `getItem/setItem/removeItem` and the actually-used `safeParse/writeJson` — with no clear indication getItem/setItem are still needed; they appear unused by the rest of the shown codebase. — Files: src/lib/storage.ts / Fix: Remove the unused getItem/setItem/removeItem trio if safeParse/writeJson is the canonical path, or consolidate into one API.
- [dead_code] src/pages/__chiptest.tsx contains only `export {}` — an empty placeholder file with no functionality, sitting in the pages directory alongside real routed pages. — Files: src/pages/__chiptest.tsx / Fix: Delete the file; if kept for a reason, move it out of pages/ and add a comment explaining why it must stay.
- [dead_code] `formatCurrency` and `cn` in lib/utils.ts are not referenced by any component/page shown (styling is done via inline style objects, not className concatenation; currency formatting elsewhere uses formatKRW/formatNumber). — Files: src/lib/utils.ts / Fix: Remove unused exports, or if they're intended for future use, verify with a repo-wide usage search before keeping them.
- [naming] lib/contract.ts uses camelCase for type aliases (`saveRecordFn`, `loadRecordsFn`, `useAppStateFn`) while the rest of the codebase (lib/types.ts) consistently uses PascalCase for types/interfaces (RemainingResult, WeeklyStats, PaceBadge). It also declares a top-level `Record` type that shadows TypeScript's built-in `Record<K,V>` utility type, which is a latent footgun for any file importing both. — Files: src/lib/contract.ts / Fix: If contract.ts is retained, rename to PascalCase (SaveRecordFn, etc.) and rename `Record`/`Budget` to non-colliding names (e.g. RecordEntry, BudgetEntry).
- [naming] Most component files follow a 1:1 file-name-to-export convention (Card.tsx→Card, MiniBar.tsx→MiniBar, DonutChart.tsx→DonutChart), but BottomCTA.tsx exports SubmitFooter/ButtonStack and StateView.tsx exports EmptyState/LoadingState — neither export name matches its filename, breaking the pattern used elsewhere and making the components harder to locate by name. — Files: src/components/BottomCTA.tsx, src/components/StateView.tsx / Fix: Rename files to match a primary export (or split into SubmitFooter.tsx/ButtonStack.tsx and EmptyState.tsx/LoadingState.tsx) to keep the file↔export mapping predictable.
- [structure] Dev-only/scratch files (__TdsGallery.tsx, __chiptest.tsx) live directly in src/pages/ next to real routed pages, relying on naming convention (leading underscore) plus a DEV-only conditional import in App.tsx to stay out of production rather than physical separation. — Files: src/pages/__TdsGallery.tsx, src/pages/__chiptest.tsx, src/App.tsx / Fix: Move dev-only pages into a separate src/dev/ or src/pages/__dev__/ directory so pages/ only contains real routes, reducing risk of them being accidentally wired into production routing.
