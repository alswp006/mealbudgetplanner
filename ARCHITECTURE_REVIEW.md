# Architecture Review
Generated: 2026-08-01T18:35:20.724Z

## Summary
The component layer is well-designed — consistent 'Pre-built, do not reimplement' documentation, a single ScreenScaffold/PageShell layout pattern, and one shared state-management approach (useAppData/useDerived) used uniformly across all pages. However, the codebase has accumulated meaningful duplication of small utilities (haptics, date formatting, digit parsing) that were never centralized, a stale/dead contract file with a type name collision, and leftover scratch files mixed into production folders.

## Issues
### Critical
- [dead_code] lib/contract.ts declares an entire set of types/fn-signatures (Transaction, Budget, formatAmountFn, calculateRemainingFn, isOverBudgetFn, useBudgetStoreFn, useTransactionStoreFn) that don't match any real implementation in the codebase (actual entities are MealRecord/MonthlyBudget, actual functions are getRemainingPerMeal/getOverBudgetStatus). Worse, it declares its own `RouteState` type with a completely different shape than the `RouteState` actually used in lib/types.ts and RecordPage.tsx, creating a name collision trap for future imports. — Files: src/lib/contract.ts, src/lib/types.ts / Fix: Delete contract.ts now that implementation has diverged from the scaffold, or rename its RouteState to something distinct and prune the unused Transaction/Budget/*Fn types that no packet ever implemented.

### Warnings
- [duplication] The exact same try/catch-wrapped generateHapticFeedback haptic helper is re-implemented independently in at least six files instead of being extracted to a shared lib/haptics.ts. — Files: src/components/BottomCTA.tsx, src/components/CheckInSection.tsx, src/components/FloatingTabBar.tsx, src/pages/BudgetPage.tsx, src/pages/Home.tsx, src/pages/RecordPage.tsx / Fix: Extract a single `fireHaptic(type)` utility into e.g. src/lib/haptics.ts and import it everywhere, so the WebView-guard try/catch logic lives in one place.
- [duplication] `todayString()` (new Date().toISOString().slice(0,10)) and the UTC-safe `addDays()` date-math helper are each reimplemented identically in multiple files rather than living in one date module. — Files: src/pages/BudgetPage.tsx, src/pages/Home.tsx, src/pages/RecordPage.tsx, src/pages/SimulationPage.tsx, src/pages/StatsPage.tsx, src/lib/calc.ts, src/lib/store.ts / Fix: Create src/lib/date.ts exporting todayString/addDays/dayOfMonth/daysInMonth, and have calc.ts, store.ts, and all pages import from it.
- [consistency] Two separate, overlapping money-formatting utilities exist and are used inconsistently: lib/format.ts's formatKRW (used by DonutChart, OverBudgetAlert, StatsPage) vs lib/utils.ts's formatNumber/formatCurrency (used by Amount, CountUp). This produces divergent output conventions (formatKRW appends '원' itself; formatNumber requires callers to append the unit manually) for the same underlying concept. — Files: src/lib/format.ts, src/lib/utils.ts, src/components/Amount.tsx, src/components/CountUp.tsx, src/components/DonutChart.tsx, src/components/OverBudgetAlert.tsx / Fix: Consolidate into a single currency/number formatting module with one clear API (e.g. formatKRW for full currency strings, formatNumber for bare digit grouping) and deprecate the redundant one.
- [dead_code] TossRewardAdMini.tsx is explicitly commented as unused leftover debug scratch and is not imported by any page or component. — Files: src/components/TossRewardAdMini.tsx / Fix: Delete the file (or if deletion is genuinely blocked in this environment, move it out of src/components into a scratch/ directory excluded from the build).
